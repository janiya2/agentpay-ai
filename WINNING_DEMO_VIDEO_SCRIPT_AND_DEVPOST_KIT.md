### 🛠️ How We Built It (Deep Technical Architecture)
* **Frontend**: Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS, Framer Motion, Lucide Icons.
* **Autonomous Intelligence**: Google Gemini 2.5 Flash SDK (`@google/generative-ai`) featuring an enterprise multi-key automatic failover rotator and semantic code analysis.
* **PayPal Payments Engine**:
  * **Inbound Escrow**: `@paypal/react-paypal-js` & PayPal Orders v2 REST API (`intent: CAPTURE`).
  * **Outbound Disbursals**: PayPal Payouts Batch v1 REST API (`/v1/payments/payouts`).
  * **Real-Time HMAC Telemetry**: Custom PayPal Webhooks ingestion engine verifying `PAYPAL-TRANSMISSION-SIG` via `SHA256withRSA`.
* **State & Persistence**: Google Cloud Firestore (multi-tenant real-time subscriptions) and Resend Transactional Email Engine.
* **Voice & Multi-Modal**: Browser `SpeechRecognition` API coupled with `MediaRecorder` audio buffer streaming and CyberVoice™ waveform visualizers.

### 🧗 Challenges We Ran Into (The FinTech Authorization Trap)
Our biggest technical hurdle was architectural: **How to execute multi-tranche milestone escrow without banking custody bottlenecks?**
* Traditional developers often attempt to use PayPal card pre-authorizations (`intent: AUTHORIZE`). However, card authorizations expire after 29 days, cannot disburse funds across multiple third-party specialists, and cannot fractionate into partial milestone releases.
* **Our Solution**: We engineered a **Dual-Rail Clearinghouse Model** (identical to the architecture employed by Upwork and Fiverr Enterprise). Capital is ingested via `PayPal Orders v2 (CAPTURE)` into an audited double-entry ledger state machine, fractionated into milestone tranches, and disbursed directly to specialists' PayPal accounts upon verified delivery via `PayPal Payouts Batch v1`.
